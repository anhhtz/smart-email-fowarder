System Architecture

Smart Email Forwarder is engineered with a modular, decoupled architecture prioritizing air-gapped autonomy, strict message deduplication, and zero external runtime dependencies.

Network Topology & LAN Isolation

In enterprise setups, email servers often reside inside restricted VLANs where worker servers are prohibited from communicating with the public internet. Smart Email Forwarder solves this by operating as an unprivileged LAN client that bridges IMAP and SMTP strictly through the local Microsoft Exchange Server:

Figure 2.1: Segregation of network responsibilities. Only the Exchange Edge connector communicates with the internet.

End-to-End Processing Lifecycle

During every polling cycle (or manual "Sync Now" trigger), the application executes the following sequential pipeline:

  1. IMAP Session Initiation: Connects to the Exchange IMAP server via TLS or STARTTLS. If configured with self-signed certificate acceptance, native OpenSSL certificate validation is customized to accept corporate root authorities.
  2. Folder Selection & Search: Selects the target folder (default: INBOX) and queries unread or unseen messages (or all messages depending on configuration).
  3. Deduplication Verification: For each candidate message, extracts the unique RFC822 Message-ID header. Queries the embedded SQLite database table processed_emails. If the ID exists, the message is skipped immediately without downloading its payload.
  4. Full MIME Retrieval & Parsing: If the message is new, the raw RFC822 message payload is fetched and parsed using mail-parser. Plain text bodies, rich HTML, inline images, and nested binary attachments are fully reconstructed.
  5. Header & Banner Synthesis:
    • Original Reply-To header is retained so replying in Gmail naturally targets the original author.
    • Configurable subject prefix (e.g., [Exchange-Fwd]) is prepended.
    • A visual forwarding summary banner is injected into the HTML and text bodies.
  6. SMTP Outbound Relay: An RFC5322 compliant message is constructed with lettre, retaining all attachments with accurate MIME content types. The message is dispatched to the internal Exchange SMTP relay, which routes the message out to the specified Gmail addresses.
  7. State Persistence & Exchange Flagging: Upon verified SMTP acknowledgment, the Message-ID, subject, sender, and timestamp are inserted into SQLite. If "Mark as Read" is enabled, the \Seen flag is stored on the message in Exchange.

MIME Parsing & Attachment Architecture

Preserving exact email formatting and file integrity is paramount. Enterprise emails regularly contain embedded signatures, company logos, Excel worksheets, signed PDFs, and compressed archives.

Part Type Handling Strategy Preservation Guarantee
Rich HTML DOM preservation with injected banner at <body> top. Styles, formatting, fonts, and hyperlinks intact.
Plain Text UTF-8 normalized with ASCII forwarding header text. Line breaks, spacing, and quotes preserved.
Inline Images (CID) Original Content-ID headers maintained. Images display inline inside email viewers.
Binary Attachments Extracted raw bytes, original filename, and MIME type preserved. Zero byte truncation or re-encoding corruption.

SQLite Deduplication Engine

The SQLite engine runs in embedded mode via rusqlite(bundled) with Write-Ahead Logging (PRAGMA journal_mode=WAL) enabled for concurrent read and write operations.

SQL SCHEMA 
CREATE TABLE IF NOT EXISTS processed_emails (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    message_id TEXT NOT NULL UNIQUE,
    subject TEXT,
    sender TEXT,
    recipient TEXT,
    processed_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    status TEXT NOT NULL,
    error_message TEXT
);

CREATE INDEX IF NOT EXISTS idx_processed_emails_message_id 
ON processed_emails (message_id);
Index-Optimized Deduplication

Because message_id has an explicit B-tree index, deduplication checks execute in sub-millisecond time (O(log n)), regardless of whether the database contains 10,000 or 1,000,000 records.

Security & Air-Gapped Compliance

Smart Email Forwarder adheres strictly to enterprise air-gapped security guidelines:

  • No Telemetry: Zero outgoing connections to analytics servers, tracking beacons, or license validation systems.
  • Credential Protection: Passwords stored in SQLite are masked (••••••••) across all REST API responses and the Web UI.
  • Memory Safety: Built 100% in Rust, preventing buffer overflows, null pointer dereferences, and memory leaks during long-running 24/7/365 service operation.
  • Session Validation: Web console interactions are authenticated via session tokens with expiration and origin checks.
