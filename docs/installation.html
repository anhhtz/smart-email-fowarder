Installation & Deployment

Smart Email Forwarder is designed to deploy seamlessly in air-gapped enterprise environments with zero external dependencies, no package managers, and no runtime installations.

Deployment on Windows Server 2019 Standard

Windows Server 2019 Standard in air-gapped production usually lacks internet connectivity. Deployment is accomplished by copying the single binary and registering it with the built-in Windows Service Control Manager (sc.exe).

Step 1: Copy Executable & Scripts

  1. Compile smart-email-forwarder.exe on a workstation or download the release artifact.
  2. Create a dedicated directory on the target server, for instance C:\SmartEmailForwarder.
  3. Copy smart-email-forwarder.exe and the deploy\windows\ scripts into that directory:
C:\SmartEmailForwarder\
├── smart-email-forwarder.exe
├── data\
└── deploy\
    └── windows\
        ├── install_service.bat
        ├── uninstall_service.bat
        └── run.bat

Step 2: Automated Service Installation

Open Command Prompt or PowerShell as Administrator and execute:

CMD (ADMINISTRATOR) 
cd C:\SmartEmailForwarder
deploy\windows\install_service.bat
What install_service.bat Does

The installer script checks for administrative privileges, registers SmartEmailForwarder with sc.exe, sets startup mode to Automatic (launches upon server boot before any user logs in), configures Crash Auto-Recovery to restart within 5 seconds, and starts the service immediately.

Alternative: Manual sc.exe Commands

If you prefer registering the service manually without the batch script:

MANUAL SERVICE REGISTRATION 
:: 1. Create the Service
sc.exe create "SmartEmailForwarder" binPath= "\"C:\SmartEmailForwarder\smart-email-forwarder.exe\" --service" start= auto DisplayName= "Smart Email Forwarder"

:: 2. Set Service Description
sc.exe description "SmartEmailForwarder" "Polls MS Exchange mailbox and forwards emails to Gmail via internal Exchange relay."

:: 3. Configure Failure Recovery (restart after 5000ms)
sc.exe failure "SmartEmailForwarder" reset= 86400 actions= restart/5000/restart/5000/restart/5000

:: 4. Start the Service
sc.exe start "SmartEmailForwarder"

Windows Firewall Configuration (Optional)

To access the Web UI from another workstation on the internal corporate network, allow inbound traffic on port 8080:

POWERSHELL (ADMINISTRATOR) 
New-NetFirewallRule -Name "SmartEmailForwarder_WebUI" `
  -DisplayName "Smart Email Forwarder Web Console (Port 8080)" `
  -Direction Inbound `
  -Protocol TCP `
  -LocalPort 8080 `
  -Action Allow

Deployment on Linux Mint & Ubuntu

On Linux systems, Smart Email Forwarder runs as a managed systemd system daemon.

Step 1: Install Binary

BASH 
# Create application directory
sudo mkdir -p /opt/smart-email-forwarder/data

# Copy binary and grant execute permissions
sudo cp target/release/smart-email-forwarder /opt/smart-email-forwarder/
sudo chmod +x /opt/smart-email-forwarder/smart-email-forwarder

Step 2: Configure Systemd Service

Copy the included unit file from deploy/linux/email-forwarder.service to /etc/systemd/system/:

/etc/systemd/system/email-forwarder.service 
[Unit]
Description=Smart Email Forwarder Service
After=network.target

[Service]
Type=simple
WorkingDirectory=/opt/smart-email-forwarder
ExecStart=/opt/smart-email-forwarder/smart-email-forwarder --port 8080 --host 0.0.0.0 --db /opt/smart-email-forwarder/data/forwarder.db
Restart=always
RestartSec=5s
LimitNOFILE=65536
Environment=RUST_LOG=smart_email_forwarder=info,tower_http=info

[Install]
WantedBy=multi-user.target

Step 3: Enable & Start Daemon

BASH 
# Reload systemd definitions
sudo systemctl daemon-reload

# Enable service on boot and start immediately
sudo systemctl enable --now email-forwarder.service

# Verify service status
sudo systemctl status email-forwarder.service

# View real-time log output
journalctl -u email-forwarder.service -f

Compiling from Source

If you are building the binary from source in an enterprise environment:

Prerequisites

  • Rust Toolchain: Rust 1.75+ (installable via rustup).
  • C Compiler: gcc/clang on Linux, or Visual Studio Build Tools (C++ workload) on Windows (required for bundling SQLite).
  • OpenSSL: OpenSSL headers (or use native Windows SChannel).

Offline Vendoring for Air-Gapped Workstations

If the build machine itself has internet access before moving into an air-gapped room, pre-vendor all crate dependencies:

BASH 
# Download and vendor all Cargo dependencies into vendor/ directory
cargo vendor

# Build in 100% offline mode without contacting crates.io
cargo build --release --frozen --offline

Cross-Compiling for Windows from Linux

# Add Windows target
rustup target add x86_64-pc-windows-gnu

# Install mingw-w64 compiler
sudo apt-get install mingw-w64

# Compile .exe binary
cargo build --release --target x86_64-pc-windows-gnu
