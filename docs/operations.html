Operations & Monitoring

Comprehensive operational runbook for monitoring service health, reading live telemetry, maintaining the embedded SQLite engine, and diagnosing network connectivity issues.

Process Monitor & Real-Time Telemetry

The Process Monitor tab in the web console surfaces deep OS-level telemetry directly from the host operating system kernel without requiring external agents like Prometheus or Datadog:

Metric Category Indicators Description & Diagnostic Value
Identity & Execution PID, PPID, Execution Mode, Uptime Distinguishes between Interactive Console, native Windows Service, or systemd daemon. Uptime confirms service longevity.
Memory Footprint RSS, VmSize, VmPeak • RSS (Resident Set Size): Actual physical RAM consumed (typically < 25 MB).
• VmPeak: Peak virtual memory allocated since startup to verify absence of leaks.
CPU & Concurrency Cores, Load Averages (1m, 5m, 15m), OS Threads Tracks active worker threads inside Tokio's asynchronous thread pool. Normal baseline is 4 to 8 threads.
Database Telemetry File size, Journal Mode, Integrity Status, Total Records Displays actual byte footprint of forwarder.db, verifies WAL mode, and shows total deduplicated email records.
Component Subsystems Poller Worker, SQLite, IMAP Connector, SMTP Connector Live operational indicators reflecting the health of each internal pipeline component.

Subsystem Health Diagnostics

Clicking "Run Diagnostic Ping" on the Process Monitor triggers on-demand microsecond latency probes across the four core subsystems:

⚡

Tokio Async Runtime

Dispatches an async task through Tokio's task queue to measure scheduling overhead and event-loop responsiveness (typically < 1 ms).

💾

SQLite Storage Engine

Performs a round-trip SELECT 1 and schema query to measure database lock latency and disk I/O performance.

🔄

Background Poller

Validates the background loop task channel, verifying that sync triggers and interval timers are actively responsive.

🌐

Exchange Connectivity

Inspects the stored credentials and endpoints to verify that IMAP and SMTP configurations are active and reachable.

SQLite Database Maintenance

The database file defaults to data/forwarder.db. By default, it operates in Write-Ahead Logging (WAL) mode, allowing concurrent reads from web dashboard users while the poller writes new message records.

Manual Integrity Verification

You can verify database consistency at any time from command line:

BASH / CMD 
sqlite3 data/forwarder.db "PRAGMA integrity_check;"
# Output: ok

Backing Up the Database

Because SQLite WAL mode guarantees ACID transactions, you can safely copy data/forwarder.db even while the service is actively running:

# Linux
cp data/forwarder.db "data/forwarder-backup-$(date +%F).db"

# Windows (PowerShell)
Copy-Item data\forwarder.db -Destination "data\forwarder-backup-$(Get-Date -Format 'yyyyMMdd').db"

Database Vacuuming

If millions of emails have been processed over years, optimize page allocation with VACUUM:

sqlite3 data/forwarder.db "VACUUM;"

Troubleshooting Guide

Issue 1: "SSL/TLS handshake failed: certificate verify failed"

Cause: Your internal Exchange Server uses a self-signed SSL certificate or an enterprise certificate authority (Active Directory Certificate Services) not trusted by the host OS default trust store.

Solution: Navigate to the Exchange Mailbox Settings tab in the Web UI and toggle "Accept Internal / Self-Signed SSL" to ON, then click "Save Settings".

Issue 2: "550 5.7.1 Unable to relay" or "Relay access denied"

Cause: The Exchange Server SMTP Receive Connector rejected outbound routing of messages destined for external domains (e.g. @gmail.com).

Solution: In Exchange Admin Center → Mail Flow → Receive Connectors:

  1. Select the connector handling internal relay (e.g., port 25).
  2. Under Scope → Remote IP addresses, ensure the host machine's IP is listed.
  3. Under Security → Permission Groups, check Anonymous users or Exchange servers.
  4. Alternatively, enable "Requires Authentication" in Smart Email Forwarder SMTP settings and supply an authorized domain user.

Issue 3: "NO [AUTHENTICATIONFAILED] Invalid credentials"

Cause: Exchange IMAP requires specific domain naming format.

Solution: Try varying the username format:

  • CORP\username (NetBIOS domain format)
  • username@corp.local (User Principal Name / UPN)
  • username (if default domain is configured in Exchange IMAP service)
